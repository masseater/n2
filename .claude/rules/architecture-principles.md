# アーキテクチャ原則

このプロジェクトで一貫して守るべき原則。

## コアコンセプト

- **ビュー切り替え型**: 同一データを日報/リスト/カンバンの3ビューで表示する
- **個人向け**: チーム機能は実装しない。シンプルなUI優先

## データモデル

- **タスク = 無限階層**: ルートタスク = プロジェクト
- **materialized path** でタスク階層を管理
- **削除はアーカイブテーブルに移動** (ハードデリートしない)

## 同期戦略

- **Last-Write-Wins**: `updatedAt` タイムスタンプで判定
- CRDTや手動マージは採用しない

## 繰り返しタスク

- **RRULE形式** (RFC 5545) を使用
- 独自形式は採用しない

## ステータス管理

- デフォルト3状態 (TODO/In Progress/Done) + ユーザー拡張可能
- ステータスは `statuses` テーブルで管理
