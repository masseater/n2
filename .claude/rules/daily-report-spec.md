# 日報機能仕様

## ワークフロー

1. 作業開始時に日報を開く
2. 各タスクについて「昨日やったこと」を振り返り記入
3. 各タスクについて「今日やること」を計画
4. 必要に応じてステータスを更新
5. 振り返り・所感を記入

## データ構造

日報はタスク主軸で設計する。

```
タスクA
  - 昨日やったこと: [Markdown入力欄]
  - 今日やること: [Markdown入力欄]

タスクB
  - 昨日やったこと: [Markdown入力欄]
  - 今日やること: [Markdown入力欄]
```

## 表示条件

日報ページに表示するタスクの条件:

1. TODO / In Progress のタスク → 表示
2. Done のタスク → その日に Done になった場合のみ表示、翌日以降は非表示
3. 手動追加機能は不要（ステータスで自動決定）

## タスク表示順序

優先度順（昇順: 1 = 最高優先度）でソートする。

- priority が小さいほど上位に表示
- priority が null のタスクは priority=10 と同等扱い（末尾に表示）
- 同一優先度内は ID 順

## 自動プレフィル機能

今日の日報を開いた時、前日の todayNote を yesterdayNote に自動プレフィルする。

条件:
- 今日の日報のみ（過去の日報では実行しない）
- 既存の yesterdayNote がない場合のみ（既存データがあればスキップ）
- ページ読み込み時に自動実行

実装:
- クライアント側で前日の日報も取得し、表示時にマージ
- DB には保存しない（表示のみ）

## ステータス変更

日報からタスクのステータスを変更すると、タスク本体の statusId が即座に更新される。
リストビュー、カンバンボードにも即座に反映される。

Done に変更した場合:
- `tasks.completedAt` を自動設定
- その日の日報には引き続き表示
- 翌日以降の日報には表示されない

## 入力形式

yesterdayNote / todayNote / notes は Markdown 形式をサポートする。

- 入力: 通常の Textarea
- 表示: タブ切替でプレビュー表示
- 保存: onBlur 時に自動保存（現状維持）

## タイムゾーン

「今日」の判定は users.timezone を基準にする。

## 週報・月報ビュー

週報・月報では以下を表示する:
- 各日のタスク一覧（Done タスクも含む）
- 各日の notes（自由記述欄）

## DB設計

### daily_report_tasks テーブル

タスクごとの日報エントリー:

- `statusId`: 日報エントリ作成時点のステータス（スナップショット）
- `nextStatusId`: その日に変更したステータス（履歴用）
- `yesterdayNote`: そのタスクで昨日やったこと（Markdown）
- `todayNote`: そのタスクで今日やること（Markdown）

## ビュー優先度

- デフォルトビュー: 日報
- タブ順序: 日報 > リスト > ボード
